## Summary

Pass 03 is worse than pass 02 (128 passed, 187 failed). 225 of the 287 failures share one cause (A): the page is signed out, so the tree never renders (205 rows) or API calls answer `401 sign in required` (20 rows).

**Cause A (confirmed by reading, not yet fixed):** most browser tests share one session created by `global-setup.ts` and stored in `results/.auth.json`. `ui.createAccount()` signs the page out through the Account menu before registering a new account, and logout revokes that session on the server (`TestLogoutRevokesAndClears`). Every later test using the shared state then starts signed out. Before `aec7444` the Sign out click never happened (the helper timed out first), so pass 02 did not show this cascade. The first signed-out failure is test 36 (`files.compact.spec.ts:106`), right after test 35 (`(T3) Compact file browser`), the first test in run order that calls `createAccount`. The domain profile uses its own storage state and has only 23 failures.

Suggested fix direction: create the extra account in a separate browser context, or clear only the page's cookie instead of calling logout, so the shared session is never revoked. Rows marked *may be masked by cause A* ran after test 35 and should be rechecked after fix A before separate triage.
