## Fix batch

Ordered by occurrences: A, B and D (2 each), then C (1). All four signatures
are fixed in code; the E scenarios are type-checked (`make e2e-lint`) but not
re-run, so every row stays open until an on-demand run passes it.

- **A (2, test defect, confirmed):** the History view lists one entry per event
  (Added, Status, Deleted), each repeating the instruction and failure detail,
  which is intended. The scenario now expects 3 instruction rows, checks the
  Added and Deleted entries, and uses `.first()` for the repeated detail.
- **B (2, test timing defect, confirmed):** the terminal's tmux client attaches
  after the pane opens, so the "before" pid was `""`. A new
  `attachedClientPid` helper in `tree.custom.spec.ts` polls until the client
  exists before capturing the pid (T4 rename, T5 hide).
- **D (2, test defect, confirmed):** opening the Command palette moves focus
  out of the phone drawer, and the drawer (a modal dialog) is dismissed, so the
  "Project tree" locator waited forever. The scenario now checks the layer
  order only if the drawer is still open, and otherwise asserts the criterion
  directly: the palette's search input is the topmost element at its center
  and filtering works.
- **C (1, app bug, confirmed):** after an app restart the events snapshot
  carries the host with status `unknown` and an empty session list; the first
  poll publishes `machine.status ok` before `sessions.changed`, so the tree
  sync treated the empty list as authoritative and pruned saved expanded and
  hidden session keys. The sessions store now leaves out a snapshot's list for
  an unprobed (`unknown`) machine until its first `sessions.changed`. New
  Vitest case in `web/src/stores/tree.spec.ts` (failed before the fix).
